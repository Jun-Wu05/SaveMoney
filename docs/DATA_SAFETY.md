# SaveMoney 数据安全、备份与恢复

SaveMoney 仅在当前设备浏览器 / 主屏幕 PWA 本地保存账本，没有账号、自动云同步或远程恢复。GitHub Pages 只提供静态应用文件，**不保存个人账单**。

## 数据存储

- 账单、分类、月度预算和分类预算：当前运行环境的 IndexedDB（Dexie 数据库 `SaveMoneyLedger`）。
- Service Worker / Cache Storage：离线应用资源，**不是账单备份**。
- 最近生成备份和手动确认保存时间：localStorage，仅用于提醒，不包含完整账本。

iPhone Safari 和主屏幕 Web App 可能有独立本地存储，**应在日常实际记账的入口导出 JSON**，不要假定不同入口共享数据。

## 建议每周备份

1. 进入 **设置 → 数据管理**，导出完整 JSON。
2. 在「文件」App 核实文件存在，保存副本到 iCloud Drive 或独立于手机的其他位置。
3. 回到 SaveMoney，人工点击「我已确认备份文件保存成功」。此操作不能证明文件已上传到云端。
4. 通过「校验 JSON 备份文件」执行只读格式检查，确认文件可识别且不修改当前账本。
5. 保留两份以上不同日期的完整备份，防止唯一文件被覆盖。

“文件已生成”“手动确认保存”“格式校验通过”是不同状态。**格式校验不等于完整恢复演练，也无法保证系统异常时一定恢复成功。**

## 从备份恢复（会覆盖当前账本）

1. 先为当前账本另存一份完整 JSON。
2. 进入 **设置 → 数据管理 → 从备份恢复**，选择可信 JSON 文件。
3. 检查备份时间、账单和分类数量、月度预算及分类预算数量。
4. 明确确认覆盖操作。恢复会替换现有账本，而不是合并。
5. 完成后检查笔数、金额、分类、预算是否正确。

流程会再次校验备份并借助 Dexie 事务恢复；但存储损坏、选择旧文件等依然可能造成风险。不要在唯一真实账本上做没有备份保护的覆盖恢复测试。

## JSON、CSV 与 Excel

| 文件 | 用途 | 能否完整恢复 |
| --- | --- | --- |
| SaveMoney JSON（`savemoney-backup` v1） | 账单、分类、月度预算、分类预算备份与覆盖恢复 | **是** |
| CSV | 账单及汇总导出；兼容账单导入、预览和去重 | **否** |
| Excel XLSX | 月度分 Sheet 和汇总导出；兼容账单导入、预览和去重 | **否** |

CSV / Excel 的导入是**追加兼容的账单数据**，不能完整还原预算及全部分类配置。导入时应检查异常行、重复记录和预览的新增笔数。

## 常见风险

| 场景 | 可能后果 | 建议 |
| --- | --- | --- |
| 手机丢失、损坏 | 无法读取本地账本 | 保留设备外 JSON 文件 |
| 卸载主屏幕 PWA、清空 Safari 数据 | 本地账本可能被移除 | 不将卸载或清空当作常规排错手段 |
| iOS 存储压力、浏览器故障 | IndexedDB 可能丢失 | 不同日期的多份备份 |
| 旧 JSON 覆盖恢复 | 新账单被旧备份替换 | 恢复前备份当前账本并核对预览 |
| 仅保留 CSV / Excel | 分类、预算信息无法完整恢复 | 以完整 JSON 为主备份 |
| Safari 与桌面 PWA 显示不同账本 | 数据不自动共享 | 从原入口导出后按需导入或恢复 |
| 服务工作线程更新/缓存旧版 | 显示旧 UI | 使用应用内更新提示，不清除网站数据 |

## 隐私

应用不会将记账数据主动上传到开发者业务服务器。用户主动共享 JSON、CSV、Excel 时，应注意文件中可能含金额、日期和备注等敏感信息。iCloud 与系统备份由相应平台管理，不等于 SaveMoney 自带云同步。
