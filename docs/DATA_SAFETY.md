# SaveMoney 数据安全、备份与恢复

SaveMoney 是**仅在本地保存账单**的 PWA。它不提供账号、云同步、远程恢复或自动云备份。GitHub Pages 只提供应用静态文件，**不会替你保存个人账单**。

## 数据存储在哪里？

- 账单、分类和预算：当前浏览器 / 网页 App 的 **IndexedDB**（Dexie 数据库 `SaveMoneyLedger`）。
- 离线页面资源：Service Worker 和 Cache Storage，**不是账单备份**。
- 最近生成备份和手动确认时间：本地 **localStorage**，只是一项提示记录，不是备份文件。

iPhone Safari 和添加到主屏幕后的网页 App 可能使用不同存储容器。不要假定它们能看到同一份账本；务必从平时记账的入口导出备份。

## 每周推荐操作

1. 在实际记账的 SaveMoney 中进入 **设置 → 数据管理**。
2. 导出**完整 JSON** 备份。
3. 在 iPhone「文件」App 中确认 JSON 文件可找到，优先将副本保存到 iCloud Drive 或其他独立于当前设备的位置。
4. 返回 SaveMoney，点击**我已确认备份文件保存成功**。这是你手动记录的状态，应用无法确认 iCloud 上传完成。
5. 使用**校验 JSON 备份文件**选择刚才保存的文件；看到“校验通过”说明文件符合当前备份格式，且此操作不会修改账本。
6. 建议保留至少两份不同日期的完整备份，避免误覆盖唯一副本。

**注意：** 格式校验不能百分之百证明文件在所有设备上都可恢复，也不能保证文件已同步到云端。不要将“已生成”“已确认”或“校验通过”理解为远程数据保护承诺。

## 恢复账本（会覆盖数据）

1. **先导出当前账本的完整 JSON**，确认文件已保存。
2. 进入 **设置 → 数据管理 → 从备份恢复**，选择 JSON 文件。
3. 查看恢复预览：账单数、分类数、预算数、备份时间。
4. 核对来源后再确认覆盖。恢复会**替换当前全部账单、分类和预算**，不会自动合并。
5. 恢复后检查总笔数、月度金额、分类和预算是否符合预期。

恢复流程使用 Dexie 事务，并在执行前再次校验 JSON；但设备存储故障、浏览器异常或误选旧文件仍可能造成问题。不要用真实唯一账本做不必要的恢复演练。

## 哪些文件能恢复完整数据？

| 文件 | 用途 | 是否可完整恢复 |
| --- | --- | --- |
| SaveMoney JSON（`savemoney-backup` v1） | 账单、分类、月度预算、分类预算 | **是** |
| CSV | 账单导入导出与表格处理 | **否** |
| Excel（XLSX） | 按月查看、汇总和分析 | **否** |

## 风险与应对

| 情况 | 可能影响 | 建议 |
| --- | --- | --- |
| 手机丢失、损坏 | 本地账本不可访问 | 定期保存独立于手机的 JSON 副本 |
| 清除 Safari 网站数据、卸载网页 App | 本地数据可能被清除 | 操作前备份，不把清理缓存当作常规排错 |
| iOS 存储压力、浏览器异常 | IndexedDB 数据可能丢失 | 保留多份异地备份 |
| 误选旧 JSON 恢复 | 当前账本被旧数据覆盖 | 先备份当前数据并检查恢复预览 |
| 只导出 CSV / Excel | 分类预算等信息不能完整恢复 | 以 JSON 作为主备份 |
| 在另一浏览器或主屏幕入口打开 | 可能出现独立空账本 | 从原入口导出 JSON，再按需恢复 |

## 隐私说明

账单由当前设备本地存储，不会作为记账数据主动上传到开发者服务器。用户主动将 JSON、CSV 或 Excel 分享给第三方时，应自行注意文件包含的金额、日期、备注等敏感信息。设备自身的系统备份或文件云盘同步由相应平台管理，不等于 SaveMoney 内建云同步。
